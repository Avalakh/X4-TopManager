## Исправления809

Completion — независимый sibling batching cue с checkinterval1s. Он больше
не зависит от сброса ветки обработки очередной порции. Только этот cue переводит
поиск в committed и вызывает сохранённый stock effect tail. Результат поиска
searching/finished иcandidate_found/exhausted записывается в ActionDefinition,
чтобы отмена эфемерного search cue не скрывала итог.

Перенесённым lifetime cue даны новые собственные имена; имена старых сохранённых
узлов не используются для объединения с новой иерархией. Неизвестные ранее
отправленные claims/приказы не сбрасываются ради миграции.

Из существовавшего военного read-back выделена ReadOwnedOrderEvidence. Она
читает фактическую очередь/default/current native order, точные Ship/Goal/Manager
claims, lifetime, stop request и ручной/приоритетный контроль. Лимиты32 queue/
16 owned order refs сохранены; projection не вызывает CanUseOwnedShip с его
кадровыми побочными действиями. Экономическая строка может получить sent только
при подтверждённом собственном приказе того же ActionDefinition. Иначе она
unknown/waiting; подтверждение приказа не означает результата торговли/добычи.
Военная проекция использует тот же уже имевшийся критерий подтверждения.
