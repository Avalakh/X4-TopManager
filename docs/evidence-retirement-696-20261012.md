# Очистка наблюдений утраченной собственности

Пробел3.8/5.1: историю отдельной станции ограничивали16 снимков,
но глобальные economy_observation/economy_history не удаляли записи
проданных или уничтоженных станций. Event tables уже имели собственную
очистку; таблицы экономической истории в неё не входили.

Source696 добавляет RetireStationEvidence перед существующим обновлением
snapshot. За вызов проверяет максимум32 станции из economy_observation,
сохраняет offset и вращает окно. Запись удаляется только при !exists или
!isplayerowned; одновременно удаляется её история. Наблюдения действующей
собственности, включая старые периоды сотрудников, сохраняются.

Использована существующая минутная cadence снимка; новых таймеров,
полного обхода каждой станции каждый tick, отмены приказов, денег,
claims/receipts или увольнения нет. Индекс keys.list читается для окна,
а проверка и удаление ограничены32 записями. Это не утверждение O(1)
для получения индекса всех станций.

MD XSD/scheduling validate696 и adapted closure PASS. Установлено698,
manifest qualified_release=false. Игровое подтверждение порционной
очистки утраты собственности пока не получено; широкие задачи остаются открытыми.
