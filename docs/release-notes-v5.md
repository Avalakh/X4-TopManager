# Выпуск v5 — пополнение экипажа для капитанов

Когда на собственных кораблях больше нет свободного обслуживающего персонала для вакансий капитанов, управляющий выбирает другой свой корабль с капитаном на борту и свободным местом. Он находит совместимую верфь или док оборудования и оформляет штатный заказ на обслуживание с наймом одного service-сотрудника. Заказ меняет только численность обслуживающего персонала: ремонт, замену или покупку оборудования, ПО, боезапаса и расходников он не включает. Текущая комплектация передаётся в API целиком как неизменяемая исходная конфигурация, чтобы штатный заказ не снял оборудование. До оплаты проверяются полномочия, деньги, совместимость и защищённые приказы, а после оплаты сохраняется точная квитанция. Пока заказ не подтверждён, второй платёж не выполняется.

После прибытия сотрудника управляющий подтверждает рост service-экипажа на выбранном корабле и обновляет кадровый кэш. Свободный service-сотрудник может быть переведён через штатный `RequestTransfer` на вакантный пост капитана. Проверенный путь нанимает по одному человеку за заказ; групповой найм требует отдельной игровой приёмки.

Короткая игровая проверка: автономный заказ `service_1_417007.669` создал build task `37373`; после прибытия к доку экипаж выбранного корабля вырос с 2 до 3, service-состав — с 1 до 2, MD-квитанция перешла в `observed`. Отдельная проба того же штатного заказа с полной комплектацией сохранила 2 двигателя, 3 орудия, щит и 6 слотов ПО. Диагностическое расширение используется только для испытаний и не входит в пакет.
