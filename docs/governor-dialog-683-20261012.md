# Реальный диалог управляющего: локальное снятие и назначение

Установлено: production674, diagnostics682. Диагностические MD/Lua
копии сверены SHA; production не менялся. Load682 принял save_004.
X4 PID18356; контроллеры load682/dialog683/check684 завершились с кодом0.
Тестовое сохранение не перезаписывалось.

`dialog683.json` фиксирует настоящий start_conversation tm_empire_roles
с actor0x4c234 на station0x4c22e/module0x4c267. Производственная cue Dialog
создала кнопку снятия; GetDialogOption прочитал её текст/активность,
SelectDialogOption(1) выбрал именно её. Прямой вызов RequestAssignment
не выполнялся. После выбора статус inactive, ManagerCue отсутствует,
проекция governor0/active0 с причиной «Управляющий снят с должности».

Штатная кнопка Back закрыла диалог. Повторное открытие с тем же реальным
сотрудником показало два действующих модуля. Выбран точный текст исходного
модуля #1. Производственная RequestAssignment сработала из настоящего
event_conversation_next_section; результат bound, тот же actor/module.
На следующем штатном цикле projection active1, ManagerCue восстановлен.

`check684.json`: защищённая попытка назначения менеджера станции возвращает
existing_post; повторное назначение текущего управляющего bound;
manager_unchanged1. Эта дополнительная проверка вызывает BindGovernor,
в отличие от чтения диалоговых кнопок, и записана отдельно.

Ограничения доказательства: вход через штатное «Ещё»/AddChoice ещё не
проверен в игре; удалённый перевод через этот UI также не проверен.
Сохранение binding через load и другие guards имеют отдельные старые
свидетельства, но task2.2 целиком пока остаётся открытой. Не считать этот
короткий тест полным прогоном или приёмкой всех кадровых функций.
