# Граница периода при изменении обеспечения станции

Пробел5.1: снимок подчинённого уже хранит cargo_capacity, но сравнение
TM_SameProvision его не учитывало. Смена пилота того же корабля также
не меняла период при сохранении assignment/ownership/operational/controlled.
В результате оценка могла объединять наблюдения с разной провизией.

Source694 добавляет к существующему bounded снимку (максимум32 подчинённых)
pilot_seed и pilot_skill из штатного pilot/skilltype.piloting. Неизвестный
пилот хранится как unknown, без фиктивного нулевого навыка. Граница периода
теперь сравнивает эти два признака и уже наблюдаемую cargo_capacity.
Старые записи без новых полей начинают новый период при первом новом снимке.
Изменение фактического объёма груза не разрывает период: это результат работы,
а не смена обеспечения. Нового анализа/планировщика/исполнителя нет.

Изменён генератор adapt_native_manager.py; staged closure пересобрано.
Сравнение с установленной production674 выявило изменение только
md/tm_factionlogic_economy.xml из13 файлов адаптированного замыкания.
Manifest source SHA обновлён генератором. MD XSD/scheduling validate694,
check_adapted_manager и check_native_manager_copy PASS; originals unchanged.
Source установлен пакетом695 (51 проверенный файл, qualified_release=false);
игровая проверка смены обеспечения и задача5.1
целиком остаются открытыми.
