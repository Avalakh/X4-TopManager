# Ротация наблюдений станций

В Scan (tm_empire_assets.xml) прежнее ограничение Observations.count < 32 каждый раз выбирало первые 32 станции из полного списка. При стабильном порядке остальные никогда не появлялись в проекции оценки.

Исходник559 сохраняет лимит32 на снимок и32 обрабатываемых объекта на шаг, но двигает круговое окно станций на32 при следующем сборе. Counts и список собственности по-прежнему собираются полностью порциями. Новые оценки не выдумываются: ReadStationEvidence сохраняет прежние требования свежести, сотрудника, периода и экономических наблюдений.

validate559.txt: XSD/scheduling PASS. station-rotation559.txt: для размеров0,1,31,32,33,64,65,127,512 арифметическая проверка подтверждает покрытие каждого индекса за ceil(N/32) снимков при неизменном списке и соблюдение лимита32. Это проверка окна, не игровая приёмка большой империи. Исходник559 не установлен; installed557 остаётся текущим пакетом.

Вкладка дополнена строкой «Показана часть станций» с фактическим числом оценок и общим числом станций из проверенной проекции. Пользователь видит, что отсутствие станции в текущей порции не означает отсутствие собственности или нулевой результат. Native economy observations собираются в штатном проходе объектов, а лимит32 подчинённых/производств отдельно помечен complete=false; эти неполные сведения не превращаются в полные данным изменением.
