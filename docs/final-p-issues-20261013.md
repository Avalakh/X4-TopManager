# Найденные случаи заключительного прогона p

## Переход cancelled → delivered у одного оплаченного заказа: уточнён последующим read-back

Последующие первичные007–009-role.json изменили вывод: тот же purchase_12_403044.514/id56223 через15 игровых секунд, observed403149.538, стал delivered. Реальный корабль UFP-742 isplayerowned, accepted=1, manager_current=1, один Recon/same_goal=1. Pending очищен, Lua state=reconciled и paid1699493 остались с первоначальными key/id. Между006 и007 записанный баланс одинаков35286793: дополнительная оплата при завершении не наблюдалась. Выборка с SHA и последовательностью: purchase12-cancel-then-built-sequence-20261013.json в run-каталоге.

Таким образом, это не подтверждённая постоянная блокировка и не доказательство окончательной отмены. Первый снимок показывал промежуточный отказ наблюдения; последующий точный сертификат готового корабля согласовал тот же заказ без повторной покупки. Обработка известной окончательной отмены и её расчёты могут потребовать отдельного сценария, но этот переход не используется как основание менять production. Точный внутренний источник промежуточного cancelled и возврат денег из него не устанавливаются.

Ниже исходное наблюдение, сохранённое для последовательности расследования.

Первичная запись `autonomy-final-p-20261013/006-role.json`: purchase_12_403044.514, Pending state=building, CompletionResult state=cancelled/reason=native_build_cancelled, наблюдение403134.531. Lua подтверждает первоначальный paid1699493/id56223; это не новая бесплатная покупка и не утверждение о возврате денег.

В текущем source CancelledBuild проверяет event.param == Tracked.$Build и записывает Tracked.$Observation cancelled. ObserveTracked сохраняет этот результат. CompletePurchase передаёт его вызывающей цели, но обновляет Pending state только для delivered. Общая проекция Runtime читает Pending state/reason. Поэтому потребитель текущего статуса получает прежний building, хотя адаптер уже знает cancelled.

Причина штатной отмены заказа и факт возврата денег пока не установлены. Их нельзя выводить из одного события cancelled. Повторная оплата не выполнялась; наличие Pending удерживает новые заказы. Пока это локальный случай для общей приёмки, а не основание прервать сбор независимых доменов.

После завершения текущего неизменяемого прогона проверить общие критерии. Предложенное по одному006 изменение Pending не выполнять без нового свидетельства: преждевременное освобождение оплаченного заказа могло бы нарушить согласование фактически построенного корабля. Текущий архив p остаётся кандидатом до общей приёмки.
