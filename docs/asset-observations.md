# Снимок собственности для вкладки

`TM_Empire_Assets` только читает native ownership, operational и orders.
Штатные find_station_by_true_owner/find_ship_by_true_owner дают всю
собственность игрока; сторонние/скрытые NPC-активы не являются входами.
Полный поиск повторяется через минуту после завершения снимка. Далее
обрабатывается максимум 32 объекта каждые пять секунд. Подробные строки
ограничены 64, счётчики охватывают весь снимок: станции, S/M/L/XL и прочие.
Период и число показанных объектов указаны в интерфейсе.

Исключения объясняются штурвалом игрока, operational или сохраняемым
существующим назначением. Само присутствие игрока пассажиром не проверяется
как запрет. Собственный sent/unknown claim показывается как поручение,
которое ещё требует подтверждения; наличие order не объявляется успешной
торговлей. При отсутствии active AI свободный актив ожидает запуска.
Подчинённые штатного менеджера станции сохраняют свои текущие назначения.

При load сбор начинается заново; нет внешней истории будущих снимков.
При утрате governor binding сбор/проекция очищаются. Наблюдения относятся
к указанному периоду, а не утверждают непрерывную текущую принадлежность.
Таблицы счётчиков проверяются UI на неотрицательные целые величины, равные
суммы типов/состояний, известные поля и период не позже проекции.
Недостающие данные не заменяются нулями.

Это часть 5.5/3.8: не готовый стратегический цикл, personnel journal или
оценка станций. Все эти обязательные задачи остаются открытыми. XML и
bounded UI fixtures проходят. load-25/ui-assets-03 подтверждает реальный
снимок 69 активов: 2 станции, 67 кораблей; waiting=5, excluded=64, rows=64.
Независимое native чтение role-assets-01 даёт те же 2/67. Причина ошибок
первых проб устранена: polling cue требует checkinterval, а строковые
ключи MD tables должны начинаться с '$'. Snapshot построен за три порции,
snapshot_from=388832.8002318, snapshot_to=388842.8121937. Frame реально создан.
