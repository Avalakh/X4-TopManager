# Границы штатного перемещения экипажа

Сверены первичные локальные источники текущей игры:

- common.xsd assign_hired_actor: проверка/событие назначения, фактическое исполнение находится в MD event handler; поддерживает controlpost и entityrole;
- Conversations.NPCAssigned: event_player_assigned_hired_actor, ожидание завершения разговора, затем штатное исполнение;
- menu_map.lua performCrewExchange: обычный экипаж перемещается PerformCrewExchange2 с точными NPCSeed, captain0/0 и checkonly; дополнительных присваиваний transit в UI нет;
- Conversations.LaunchCrewTransferPod: сохраняет реальный срок прибытия, планирует запуск; состояние NPC может требовать дальнейшего штатного пути;
- NPC_Instantiation: размещённый обычный экипаж может быть temporary; это не ошибка само по себе.

Положительный обычный controlpost transfer629 уже observed. Bulk transfer636 отправлен штатным API, человек перешёл source→target, но полного прибытия за короткий период нет. Старый сохранённый unknown, посещённый пассажиром640, также не завершился за30s. Эти случаи нельзя отождествлять или выдавать успешный controlpost transfer за весь bulk путь.

Оснований заменять bulk API повторным assign_hired_actor для уже перемещённого человека не найдено: это было бы повторной операцией с прежним source, где человек отсутствует. Старую квитанцию не сбрасывать, не создавать замену сотруднику, не принуждать transit/arrival. Пока не доказана точная причина, product transport не менялся. Продолжение работы допустимо по независимым сценариям строительства, флота и причинных оценок; их завершение по этому аудиту не заявляется.
