# Наблюдение снабжения после остановки цели

Source564 добавляет RestockResultWatch в TM_Empire_Supply. Каждые15s при payment_approved/build_observed вызывается существующая ReadRestockResult с исходными key/manager/goal квитанции. Чтение не требует действующей доменной цели: подтверждённые заказ, оплата, собственность корабля и изменение инвентаря остаются обязательными.

Ранее такое чтение выполнялось только StepRestockDelivery/ConsumeRestockResult действующей цели. После её отмены отправленный заказ мог завершиться без обновления состояния. Новый watcher только обновляет квитанцию, не вызывает QuoteRestock/ApproveRestockPayment/SupplyPaid/ConsumeRestockResult и не создаёт приказов. Неопределённые результаты не повторяются и не объявляются завершёнными.

validate564.txt: XSD и проверка расписания MD PASS. Изменение ещё не установлено и не проверено в игре. Завершённая квитанция принимается прежним механизмом ConsumeRestockResult; автоматическая передача старого результата новому управляющему этим изменением не заявляется. Военная сквозная приёмка3.6 остаётся открытой.

Развитие source565: watcher также принимает completed/rejected_before_effect старой отменённой цели, но только когда её точный claim manager/goal уже отсутствует. При живой цели принятие остаётся её обязанностью. При старом claim watcher не вызывает остановку приказов; ждёт существующий механизм освобождения. Новое назначение чужого manager/goal не отменяется. ConsumeRestockResult сохраняет результат в самой исходной квитанции, а в GoalCue пишет только если cue ещё существует. Подтверждённая terminal квитанция становится consumed и больше не блокирует последующее снабжение; unknown не принимается. validate565 PASS. Source565 ещё не установлен, сценарий в игре не квалифицирован.
