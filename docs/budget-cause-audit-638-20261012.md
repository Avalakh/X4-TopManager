# Сверка причин нехватки бюджета

ReadStationEvidence использует сохранённый underfunded с фактическими money/productionmoney и отделяет состояние обеспечения от доказанного влияния на простой. Рекомендация показывает разницу счёта с производственной потребностью; ответственность менеджера по одному снимку не устанавливается.

В observation генераторе underfunded требует собственного счёта, разрешённой торговли и счёта не выше90% productionmoney. Поэтому прежняя фабрика с owner_only1 не давала автоматического пополнения/бюджетного вывода по одному сравнению100000<135600Cr: торговое ограничение наблюдалось отдельно. После подготовки630 разрешённая покупка и150000Cr соответствовали достаточному бюджету. Подтверждённого дефекта этой границы не найдено, production code не менялся.

Отдельно уточнена цепочка кадрового транзита по debug.log: сотрудник сначала имел actor0x4bc29 у получателя, затем временный roleentity исчез. Изменять temporary или transit ради принятия теста оснований нет; следующая проба штатного присутствия игрока должна различить инстанциацию и логическое прибытие. Последний read637 по-прежнему не доказывает прибытие.
