# Отзыв разрешения на обмен экипажем

Доказанная граница: RequestTransfer записывает `check_requested`, MD после штатной проверки разрешает `approved`, затем отдельное событие Lua вызывает PerformCrewExchange2. `RevokePurchaseApproval` и список `RevokeGoalApprovals` до633 не включали `$tm_empire_crew_exchange_request`. Поэтому смена назначения управляющего или отмена цели между проверкой и Lua могла оставить разрешение действующим.

Минимальная адаптация существующего механизма: crew request включён в список отзывов вместе с Transfer receipt; check_requested/approved отзываются при утрате назначения и отмене соответствующей цели. Никакого нового исполнителя нет.

ObserveTransfer различает отозванное разрешение до эффекта и уже отправленный/неизвестный результат. Только при отсутствии sent/unknown того же ключа receipt становится rejected с причиной crew_exchange_revoked_before_effect. Lua записывает unknown перед native эффектом, поэтому неопределённый реальный результат сохраняется и не отправляется повторно. Вкладка переводит новую причину на русский.

Проверки633: MD XSD/расписание PASS (`validate633.txt`), адаптированный Manager PASS, Lua crew contract PASS, включая событие submit после revoked — native effect count не увеличился. Проверка Lua доказывает отказ использовать отозванное разрешение, но не является игровой пробой отмены MD цели. Изменения633 пока не установлены; последняя установленная production сборка622–623. Задачи2.4/3.7/4.2 остаются открытыми до пакетной игровой проверки.

Дополнение634: добавлен CrewApprovalLoaded на event_game_loaded. Для совпадающего native_bulk receipt в sent/unknown сохранённые состояния запроса check_requested/approved отзываются, затем вызывается обычное ObserveTransfer. Реальный Lua результат sent/unknown сохраняется; отсутствие такого результата переводит неотправленный запрос в rejected без нового эффекта. Причина запроса crew_load_reapproval_required отличает загрузку от смены назначения. Lua init сам не переотправляет сохранённые события, поэтому до этой правки проверенный, но неотправленный запрос мог оставаться в ожидании потерянного события. Проверки MD и адаптированного Manager634 прошли (`validate634.txt`); игровая проверка загрузки ещё требуется.
